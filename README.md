# portscan

Go-пакет для проверки TCP-портов. Он устанавливает обычное TCP-соединение с каждым адресом и портом и возвращает результат проверки. Пакет использует только стандартную библиотеку Go.

Требуется Go 1.25.5 или новее.

## Пример

```go
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/KamaPulaEzhe/portscan"
)

func main() {
    scanner, err := portscan.New(
        portscan.WithConcurrency(10),
        portscan.WithConnectTimeout(500*time.Millisecond),
    )
    if err != nil {
        log.Fatal(err)
    }

    ports, err := portscan.Range(8000, 8002)
    if err != nil {
        log.Fatal(err)
    }
    ports = append(ports, 443)

    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()

    results, err := scanner.Scan(ctx, []string{"127.0.0.1"}, ports)
    if err != nil {
        log.Fatal(err)
    }
    for r := range results {
        fmt.Printf("host=%s ip=%s port=%d state=%s duration=%s err=%v\n",
            r.Host, r.IP, r.Port, r.State, r.Duration, r.Err)
    }
    if err := ctx.Err(); err != nil {
        log.Printf("scan context ended: %v", err)
    }
}
```

В примере проверяются порты 8000–8002 и 443 на локальном компьютере. `Range` включает обе границы. Если нужны только отдельные порты, вместо `Range` можно передать, например, `[]int{80, 443}`.

## Как работает сканер

`New` создаёт сканер с настройками. Без опций он запускает до 10 подключений одновременно и ждёт каждое не более секунды. Число подключений и таймаут можно изменить через `WithConcurrency` и `WithConnectTimeout`. Оба значения должны быть положительными.

`Scan` принимает контекст, хосты и порты. До запуска проверок он валидирует входные данные и разрешает DNS-имена; если это не удалось, возвращает ошибку. После этого метод возвращает канал результатов. Одним сканером можно пользоваться повторно, в том числе из нескольких горутин. Ограничение числа подключений действует отдельно для каждого вызова `Scan`.

В качестве хостов подходят IPv4, IPv6 и DNS-имена. Если имени соответствует несколько IP-адресов, проверяется каждый из них. Если два разных имени указывают на один IP, в результатах они остаются отдельными хостами. IPv6-адреса с зоной, например `fe80::1%en0`, не поддерживаются.

Пустые списки, пустые хосты, порты за пределами 1–65535 и обратные диапазоны приводят к ошибке. Пробелы по краям хостов удаляются; точные повторы хостов и портов проверяются один раз. Порядок результатов не гарантируется.

## Результаты

Каждый `Result` содержит переданный `Host`, конкретный `IP`, `Port`, состояние `State`, длительность попытки `Duration` и ошибку `Err`. Успешное соединение закрывается сразу после проверки.

| Состояние | Что произошло |
| --- | --- |
| `Open` | TCP-соединение установлено. |
| `Closed` | Подключение явно отклонено. |
| `Timeout` | Время подключения истекло, пока контекст сканирования был активен. |
| `Unreachable` | Узел или сеть недоступны. |
| `Canceled` | Контекст сканирования был завершён к моменту классификации ошибки. |
| `Error` | Произошла другая ошибка подключения. |

Успешное соединение даёт `Open`, даже если контекст отменился к моменту классификации. Ошибки определяются через `errors.Is` и `errors.As`, без сравнения текста.

## Отмена

При отмене контекста сканер прекращает работу и закрывает канал результатов. Часть результатов может отсутствовать: **`Canceled` не гарантируется для каждого порта**, в том числе для уже начатой проверки.

Если результаты больше не нужны, отмените контекст: иначе воркеры могут остаться ждать читателя. После закрытия канала можно проверить `ctx.Err()`. Учтите, что ненулевое значение показывает состояние контекста на момент проверки, но само по себе не доказывает, что сканирование было прервано до завершения.

## Тесты

```bash
go test -race ./...
go vet ./...
```

Тесты используют локальный TCP-listener и подмену dialer для проверки сетевых ошибок и отмены. Обработку нескольких DNS-адресов отдельным тестом с подменой резолвера пока не проверяем.

## Ограничения

Пакет выполняет только TCP Connect scan. Он не реализует SYN- и UDP-сканирование, определение ОС или обход фильтрации. Таймаут сам по себе не объясняет, почему цель не ответила. Слишком высокая конкурентность может упереться в лимит файловых дескрипторов ОС.

VPN в TUN-режиме с fake-IP или проксированием может искажать DNS и результаты TCP-подключений: недоступные адреса могут выглядеть открытыми. Для локальной проверки используйте `127.0.0.1`; внешние цели проверяйте с учётом настроек VPN и с разрешения их владельца.
